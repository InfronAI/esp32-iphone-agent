# Playbook：将研究性项目整理并同步到 GitHub

[返回项目](../../README.zh-CN.md) · [文档导航](../guide/README.md)

适用场景：将本地研究原型、硬件实验或 AI Agent 项目发布到指定 GitHub 仓库，
同时交付可理解的双语首页、可复现的安装方法、可在线播放的 Demo 和明确的验证记录。
首次整理日期：2026-10-24。本文来自 ESP32 iPhone Agent 的实际发布过程，也可用于其他项目。

完成标准是：陌生读者能在首页了解项目，用公开文件复现已实现部分，并清楚区分已测能力、模拟演示和待验证项。

## 1. 明确输入与交付物

先从现有对话、仓库和检测记录取得信息；只有缺失信息会影响正确性或发布范围时才询问。

| 输入 | 需要记录的内容 |
|---|---|
| 发布目标 | 仓库完整地址、目标分支、公开范围；核对 owner，不能默认当前 `origin` 就是目标 |
| 当前实现 | 实际入口、运行模式、固件/App/服务版本；历史方案与现用方案的区别 |
| 授权范围 | 是否已明确要求上传源码、文档、视频、部署在线演示；不把授权扩大为联系他人或改写历史 |
| 硬件与环境 | 检测日志、实物型号、内存、接口、构建参数；未知项保留未知 |
| 验证证据 | 测试输出、真实设备观测、截图、已知限制、尚缺的硬件 |
| 内容语言 | README、视频字幕、演示界面、手机画面和日志分别需要哪些语言 |

建议交付目录：

```text
README.md                    英文首页：项目概览、原生视频、快速开始
README.zh-CN.md              中文首页：同等覆盖范围
LICENSE / NOTICE.md         原有许可与新增贡献、第三方组件归属
SECURITY.md                  凭据配置与敏感信息报告方式
docs/guide/                 硬件、架构、流程、数据流、安装、使用、验证
docs/demo/                  分语言 MP4、海报、章节、独立播放器与重录说明
tools/demo/                 可重复录制脚本、合成夹具、语言资源
tools/ci/                   CI 模板与启用说明（适用时）
```

在已有明确发布授权时，直接完成该范围内的整理、检查和推送。需要额外授权的操作，应先准备可审阅的具体结果，
说明新增操作及原因；不要为已授权的常规步骤重复征求确认。

## 2. 建立事实记录，再写项目介绍

将能力分成四种证据状态，首页、指南和视频保持一致：

| 状态 | 可以说明什么 | 不能据此推出什么 |
|---|---|---|
| 已实现 | 有代码与接口，可说明设计和行为 | 不代表真实环境已通过 |
| 自动化验证通过 | 指明测试范围、环境和结果 | 单元测试不能证明硬件端到端成功 |
| 实机验证通过 | 指明设备、接线、输入与实际观测 | 一次枚举、连通或截图不代表整个任务闭环 |
| 模拟或待验证 | 明确夹具、替代环节、缺失条件 | 不把模拟结果写成产品实测成绩 |

硬件记录区分 **芯片、模组、开发板**。芯片 revision、Flash/PSRAM 容量或固件生成的 USB 名称不能唯一确定开发板品牌。
具体料号来自推断时，写出检测特征和官方对照依据；参考采购型号与当前实物型号分列。
记录物理容量与实际固件配置，例如“16 MB Flash，但构建采用 8 MB 分区”。

本项目示例：芯片特征对应 ESP32-S3R8；ESP32-S3-WROOM-1-N16R8 是同规格参考模组；载板商品型号仍待实物确认。
实际 USB 主机为 Mac 时，枚举成功不能证明 iPhone HID 已可用。依据与细节见[硬件记录](../guide/hardware.md)。

## 3. 整理可公开文件与许可

1. 读取适用的 `AGENTS.md`，检查 `git status`、分支、远端、子模块、忽略规则和未提交变更。
2. 明确应发布的文件清单；包含源码、依赖锁定文件、示例配置、文档和必要媒体。
3. 排除 API Key、Wi-Fi 密码、控制令牌、签名证书、私钥、个人路径、原始私人画面、编译缓存和设备私有日志。
4. 结合已知本地凭据与通用模式扫描文本和二进制元数据。输出文件名和规则名，不输出命中的秘密内容。
5. 保留原有 LICENSE 和版权信息；为新增贡献及第三方组件补齐 NOTICE。不要把已有项目的许可归属整体改成自己。
6. 检查文件体积、符号链接目标、README 相对链接、可执行权限和构建入口。

`.gitignore` 不会移除已经跟踪的秘密；“当前文件干净”也不代表准备推送的历史干净。
若发布已有历史，应检查将推送的提交；若发布审查后的快照，应明确保留原作者归属，并说明其来源。
发现已经外泄的凭据时，需要撤销或轮换，而不是只删除当前文本。

工作区仍包含大量实验修改，或当前远端指向上游时，建立**独立发布 checkout**，
以目标仓库为基线，只同步审核后的文件。保留目标仓库已有内容与历史；不重置用户工作区，不默认强推。

## 4. 写出可快速预览的中英文首页

每份 README 都应独立回答这些问题：

| 首页内容 | 写法 |
|---|---|
| 一句话定位 | 谁提出什么目标，系统完成什么，主要执行位置在哪里 |
| 当前能力 | 用已实现的具体行为描述；把关键限制放在相关能力旁边 |
| 可播放 Demo | 首页直接播放，说明时长、语言和模拟/实机边界 |
| 硬件与参数 | 具体型号或有依据的推定、核心参数、必须的适配器 |
| 开发接线 | 编译、烧录、App 安装、串口调试；说明 USB 主机是谁 |
| 实际应用接线 | 电源、数据线、手机接口、网络、可选监控端；单独绘图 |
| 项目架构 | 各模块职责、运行位置、云端依赖、历史模式区别 |
| 业务流程 | 从首次配置、提交目标、循环执行到完成、停止与失败 |
| 数据流 | 画面、模型请求、动作、状态与凭据分别经过哪里 |
| 代码结构 | 主要目录职责及常见修改入口 |
| 安装与使用 | 前提、命令、初次配置、运行入口和可操作的示例 |
| 验证记录 | 已测环境、结果、限制、后续复现条件 |

首页应有足够正文帮助读者理解整个项目，详细指南链接放在对应摘要之后。中英文内容范围一致，
避免英文首页只剩一句介绍和一组中文文档链接。仓库 description 单独写成简短英文，不堆配置细节。

Mermaid 图使用明确方向与标签，区分 USB 数据、供电、LAN 视频、云端 HTTPS 和状态监控。
开发与运行接线分开，避免一张图同时暗示板子以同一 USB 设备口连接两个主机。

## 5. 制作可信、可重录、分语言的 Demo

推荐情节：项目架构 → 登录 → 监控与状态 → 示例目标 → 输入与决策 → 动作与反馈 → 完成复核 → 卡住重规划/停止 → 配置 → 验证边界。
研究项目通常用约 60–90 秒完成这个预览；时长按内容调整。

录制前确定：

- 实际录制哪一层界面，哪些数据由真实设备提供，哪些由夹具提供。
- 模拟演示全程显示标识，开头和结尾再解释验证边界。
- 夹具拦截外部请求，使用示例凭据与域名；录制不会意外调用付费模型或发送硬件指令。
- 英文版本包含英文字幕、界面标签、模拟手机内容、目标、模型观察和动作结果；只翻译标题不算英文视频。
- 如果为录制加入语言覆盖层，说明它是 Demo 标签翻译，不能让读者误以为固件已交付完整多语言支持。

保留脚本和夹具。可以用 Playwright 截取实际界面的 PNG 帧，再以 ffmpeg 编码为 H.264、yuv420p、faststart MP4。
导出后检查真实画面，尤其是长英文换行、日志可读性、字幕遮挡、色彩、完成与停止分支。
按真实导出时间生成章节，不手填未经校准的时间点。

本项目可重复执行：

```bash
npm ci --prefix tools/demo
node tools/demo/record-demo.cjs --lang en
node tools/demo/record-demo.cjs --lang zh-CN
```

浏览器安装与本机 Chrome 的使用方法见[录制说明](../demo/README.md)。
分语言维护视频、海报、章节和 README 附件映射，更新其中一种语言时保留另一种。

## 6. 同时满足首页播放和独立在线播放

这两种交付分别验收：

| 入口 | 做法 | 验收 |
|---|---|---|
| GitHub README 首页 | 上传 MP4 为 GitHub 视频附件，将稳定附件地址单独成段放入对应 README | 首页实际出现播放器，可以点击播放，不是海报跳转或下载链接 |
| 独立在线页面 | 静态 `<video controls playsinline>`，配海报、章节、下载链接、语言选择与边界说明 | 无登录可播，可拖动进度，移动端正常 |

GitHub CLI 官方附件能力支持对 issue、PR 和评论上传文件并生成内联媒体地址；
使用前核对 CLI 版本与权限。[官方附件说明](https://docs.github.com/en/github-cli/github-cli/attaching-files-with-github-cli)。
如果任务只要求 README，不要为了得到附件地址擅自新建 issue、评论或向他人发消息；使用可用的独立上传能力或仓库编辑器上传。

README 使用稳定的 `github.com/user-attachments/assets/...` 地址，避免保存会过期的签名 CDN URL。
**替换仓库中的 MP4 不会替换已有附件**：重新上传后还要更新对应 README 的附件地址。
中文与英文不能误用同一个语言的视频。

独立播放器可通过 GitHub Pages 发布，本项目使用 `main` 分支的 `/docs`，并以 `.nojekyll` 保留静态文件。
GitHub Pages 也支持自定义 Actions 部署，按实际项目选择。[发布源配置](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。
Pages 部署成功与项目测试 CI 通过是两件事，不能互相替代。

## 7. 验证、提交与推送

按改动范围检查，不重复运行无关测试：

- 固件或硬件协议变化：目标构建、相关逻辑测试、必要的实机检查。
- App 行为变化：构建、相关测试和设备安装验证。
- 网页行为变化：浏览器交互、断连/停止等相关分支、主要屏幕尺寸。
- 纯文档或视频变化：事实、相对链接、渲染、语言完整性、媒体元数据和实际播放；不需要因此重烧固件。

在发布 checkout 中审阅差异，精确暂存文件并检查 `git diff --cached --check`。
准备推送前 fetch 目标分支，若出现并发修改先合并保留；不以强推覆盖远端内容。
提交信息围绕最终变更，逐步检查 commit 和 push 的退出状态，避免前一步失败后仍误报后续成功。

认证按能力判断：GitHub App、`gh`、Git HTTPS 和浏览器会话可能使用不同权限。
某个连接器无写权限或 `gh` 未登录，不代表已经配置的 Git HTTPS 凭据失效。
优先使用能完成任务的连接器；能力不足时说明原因并使用已有可用方式。密钥不写进命令、文档或日志。

遇到 workflow 权限不足时，不能宣称 CI 已启用。本项目将测试工作流保留在 `tools/ci/` 作为模板，
另外使用 Pages 的分支发布。模板、部署和测试状态分别记录。

## 8. 用陌生读者的访问方式验收

1. 核对目标仓库的 HEAD 提交与本次提交一致，关键文件内容或 Git blob 哈希一致。
2. 以无登录会话打开中英文 README，检查图片、图表、相对链接和对应语言的原生视频。
3. 实际点击播放，确认时间推进；拖动到中后段，检查画面与音视频加载，不只看 HTTP 200。
4. 打开在线播放器，核对 MIME、Range/拖动播放、章节跳转与手机版布局。
5. 等待实际 Pages 部署结果，确认公开页面已读取新版本；本地预览不算线上验收。
6. 记录提交 SHA、部署地址、视频语言与时长、检查结果和仍待验证的能力。

附件裸地址的单独请求结果不能替代 README 渲染结果；实际页面中的原生播放才是该入口的验收对象。
浏览器自动化应等待页面完成加载并正确定位播放控件，避免把点击进度条误判成播放失败。

## 9. 交付记录模板

```text
仓库与分支：
发布提交 SHA：
主要入口：英文 README / 中文 README / 在线 Demo / 指南
英文视频：文件、稳定附件 URL、时长、语言与模拟/实机性质
中文视频：文件、稳定附件 URL、时长、语言与模拟/实机性质
源码检查：通过项、范围、日志位置（不含秘密）
公开页面检查：匿名播放、拖动、章节、手机布局
硬件验证：设备、接线、已测结果、尚缺条件
许可与凭据审查：结果及排除项类别
下次更新：重录命令、附件更新规则、部署入口
```

最终给用户报告已发布的结果、可点击入口和有影响的剩余限制。
未完成的硬件闭环可以作为明确限制发布；不要把它写成通过，也不要因此遗漏已获授权且可以独立完成的源码、文档和演示交付。

## 本次实践留下的经验

| 情况 | 可复用的处理方式 |
|---|---|
| 本地 `origin` 指向原作者仓库 | 独立 clone 指定发布仓库，核对 owner 后同步审核文件 |
| 不能确认开发板商品型号 | 给出检测事实、推定依据和具体参考模组，保留载板未知项 |
| 开发与运行 USB 主机不同 | 两套接线图分别说明，避免错误确认手机主机或在 Mac 上校准 |
| 缺少手机 USB 主机适配器 | 公开已验证链路，Demo 显示模拟边界，保留实机验证待办 |
| README 放 MP4 链接仍不能首页播放 | 使用原生视频附件，匿名打开 README 实际点击验证 |
| 英文 README 播放的是中文素材 | 单独生成英文界面、字幕、手机画面与日志，并更新英文附件 |
| 更新 MP4 后首页仍是旧视频 | 独立更新 GitHub 附件 URL；Pages 视频与附件各自检查 |
| 推送成功但网站暂未更新 | 检查 Pages 部署和公开版本，不用本地状态代替线上结果 |
| 凭据缺少 workflow 权限 | 说明未启用 CI，保留模板，不阻塞已授权且可完成的源码发布 |

这个 playbook 记录当前流程和经验；再次使用时应重新核对工具、平台权限与项目事实。
