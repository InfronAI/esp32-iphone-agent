## 延迟诊断结论的边界

先前实测截图 HTTP 传输多为约 0.07–0.18 秒，解码显示队列额外保留一帧会在低输入帧率下显著增加等待。
同一 H.264 在 Mac FFmpeg 正常、OpenH264 出现残影；修正长期参考帧编号后本地主机对照消除了像素差异，
并通过 I/P 显示队列排空消除了额外一帧等待。不能因此直接宣称真机端到端延迟为某个毫秒值。

网页 5 秒更新是清晰度/负载的选择，会引入显示等待。`frame_age_ms` 和 `pipeline_ms` 是板内/接收时间指标，
不是 iPhone 拍屏计时或从手机采集开始的全链路测量。

## 如何补齐实机验收

1. 按硬件文档接好手机 USB 主机、启用辅助触控并确认真实指针。
2. 恢复镜像，先确认设置/主屏切换与网页画面一致。
3. 校准后执行只读目标“打开设置 Wi-Fi 页并读取网络名”。
4. 同时记录真实手机外观、网页时间线和每轮画面；核对动作坐标、状态和最终复核。
5. 再验证停网、关闭镜像、锁屏、停止任务、无进展路径；确认没有迟到动作。
6. 使用脱敏的实验设备和账号录制真实 Demo，再替换当前模拟演示，更新此页结论。
